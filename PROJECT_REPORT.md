ВВЕДЕНИЕ

Современный рынок мобильных приложений демонстрирует устойчивый рост в сегменте электронной коммерции. По данным аналитических агентств, доля покупок, совершаемых через мобильные устройства, ежегодно увеличивается. Это обусловлено удобством использования смартфонов для поиска товаров, сравнения цен и оформления заказов [1].

Настольные игры представляют собой специфический сегмент товаров, требующий от покупателя возможности ознакомиться с характеристиками продукта: количеством игроков, возрастным ограничением, описанием правил и комплектацией. Кроме того, для данной категории товаров характерно наличие множества изданий и версий одной игры, что требует продуманной структуры каталога [2].

Целью данной работы является разработка мобильного приложения интернет-магазина настольных игр для операционной системы (далее — ОС) Android, обеспечивающего полный цикл покупки: от просмотра каталога до оформления заказа с указанием адреса доставки.

Для достижения поставленной цели необходимо решить следующие задачи:
- провести анализ предметной области и существующих решений;
- сформулировать функциональные требования к приложению;
- спроектировать архитектуру клиент-серверного решения;
- спроектировать пользовательский интерфейс приложения;
- реализовать мобильное приложение на языке Java;
- реализовать серверную часть для хранения данных и обработки запросов;
- провести тестирование разработанного приложения.

Объектом исследования является процесс покупки товаров через мобильное приложение. Предметом исследования выступают методы и средства разработки мобильных приложений для ОС Android.

Практическая значимость работы заключается в создании функционального приложения, демонстрирующего современные подходы к разработке мобильных приложений электронной коммерции с интеграцией картографических сервисов.


1 АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ

1.1 Актуальность разрабатываемого приложения

Рынок настольных игр в России демонстрирует стабильный рост. Покупатели данной категории товаров предъявляют особые требования к информативности карточки товара: им важно знать количество игроков, рекомендуемый возраст, время партии и содержимое коробки. Мобильное приложение позволяет предоставить эту информацию в удобном формате с возможностью просмотра нескольких изображений товара [3].

Ключевой проблемой при оформлении заказа является корректный ввод адреса доставки. Ошибки в адресе приводят к задержкам доставки и дополнительным затратам. Для решения этой проблемы в приложении реализована интеграция с картографическим сервисом 2ГИС, обеспечивающим качественные адресные подсказки для российских городов [9].

Ещё одной важной особенностью является необходимость возрастной маркировки товаров. Некоторые настольные игры имеют ограничение 18+, что требует реализации механизма предупреждения пользователя перед просмотром такого контента.

1.2 Обзор аналогичных решений

Для определения функциональных требований к разрабатываемому приложению был проведён анализ существующих решений в области мобильной электронной коммерции. Рассмотрены приложения крупных маркетплейсов (Ozon, Wildberries, Яндекс Маркет), а также специализированных магазинов настольных игр.

Анализ показал, что современные приложения электронной коммерции обладают следующими общими характеристиками:
- отображение каталога товаров в виде сетки карточек;
- возможность быстрого добавления товара в корзину из каталога;
- отображение скидочной цены с зачёркнутой старой ценой;
- изменение количества товара в корзине кнопками «плюс» и «минус»;
- удаление товара из корзины жестом смахивания;
- автодополнение адреса при вводе;
- выбор точки доставки на карте.

1.3 Постановка задачи

На основании проведённого анализа сформулированы следующие требования к разрабатываемому приложению:
- реализация авторизации и регистрации пользователей;
- отображение каталога товаров с сортировкой по наличию;
- просмотр детальной информации о товаре с несколькими изображениями;
- управление корзиной покупок (добавление, изменение количества, удаление);
- оформление заказа с вводом адреса доставки;
- интеграция с картографическим сервисом для выбора адреса;
- реализация возрастного ограничения для товаров категории 18+;
- сохранение корзины на сервере для доступа с разных устройств.


2 ПРОЕКТИРОВАНИЕ ПРИЛОЖЕНИЯ

2.1 Функциональные требования

Функциональные требования к приложению сформулированы в виде пользовательских сценариев (User Stories):

1. Как пользователь, я могу зарегистрироваться в системе, указав электронную почту, логин и пароль.
2. Как пользователь, я могу войти в систему и продолжить работу без повторного ввода учётных данных.
3. Как пользователь, я могу просмотреть каталог товаров и увидеть информацию о наличии.
4. Как пользователь, я могу открыть карточку товара и просмотреть изображения и описание.
5. Как пользователь, я могу добавить товар в корзину из каталога или карточки товара.
6. Как пользователь, я могу изменить количество товара в корзине.
7. Как пользователь, я могу удалить товар из корзины жестом смахивания.
8. Как пользователь, я могу оформить заказ, указав адрес доставки с помощью подсказок или карты.
9. Как пользователь, я вижу подтверждение успешного оформления заказа.

2.2 Архитектура системы

Разрабатываемая система построена по клиент-серверной архитектуре. Мобильное приложение выступает в роли клиента и взаимодействует с сервером посредством протокола передачи гипертекста (Hypertext Transfer Protocol, HTTP). Сервер обрабатывает запросы, работает с базой данных и обращается к внешнему картографическому сервису для получения адресных подсказок [4].

Архитектура системы включает следующие компоненты:
- мобильное приложение для ОС Android, реализованное на языке Java;
- сервер приложений на базе фреймворка FastAPI (язык Python);
- база данных SQLite для хранения информации о товарах, пользователях и заказах;
- внешний сервис 2ГИС для адресных подсказок и отображения карты.

Взаимодействие между компонентами осуществляется следующим образом:

1. Мобильное приложение отправляет HTTP-запросы к серверу через библиотеку Retrofit.
2. Сервер проверяет токен авторизации JSON Web Token (JWT) и обрабатывает запрос.
3. При необходимости сервер обращается к программному интерфейсу приложения (Application Programming Interface, API) сервиса 2ГИС.
4. Сервер формирует ответ в формате нотации объектов JavaScript (JavaScript Object Notation, JSON) и отправляет его клиенту.
5. Для отображения карты мобильное приложение загружает HTML-страницу с библиотекой 2ГИС MapGL в компонент WebView.

2.3 Проектирование пользовательского интерфейса

Пользовательский интерфейс приложения разработан в соответствии с рекомендациями Material Design 3, что обеспечивает единообразие элементов управления и соответствие ожиданиям пользователей ОС Android [8].

Приложение состоит из следующих экранов:
- экран авторизации (LoginActivity) — начальный экран с полями ввода логина и пароля;
- экран регистрации (RegisterActivity) — форма создания учётной записи;
- каталог товаров (MainActivity) — сетка карточек товаров с кнопкой корзины;
- карточка товара (GameDetailActivity) — детальная информация с изображениями;
- корзина (CartActivity) — список добавленных товаров с итоговой суммой;
- оформление заказа (CheckoutActivity) — форма ввода данных доставки;
- выбор на карте (MapPickerActivity) — интерактивная карта для выбора адреса;
- успешный заказ (OrderSuccessActivity) — подтверждение оформления.

Для обеспечения единообразия оформления элементов интерфейса определены стили в файле ресурсов themes.xml. Цветовая схема приложения основана на синем (основной цвет) и оранжевом (акцентный цвет) оттенках.

2.4 Проектирование базы данных

База данных системы реализована на основе системы управления базами данных (СУБД) SQLite. Выбор обусловлен простотой развёртывания и достаточной производительностью для задач демонстрационного приложения [10].

Структура базы данных включает 15 таблиц, которые можно разделить на следующие группы:

Справочные таблицы:
- Role — роли пользователей (покупатель, администратор);
- Status — статусы наличия товара и заказа («В наличии», «Нет в наличии», «Новый заказ»);
- AgeRating — возрастные рейтинги (0+, 6+, 12+, 18+);
- Language — языки издания (русский, английский);
- Genre — жанры игр (стратегия, кооперативная, карточная).

Таблицы пользователей:
- User — пользователи системы (логин, email, хэш пароля, имя, телефон);
- Address — адреса доставки пользователей.

Таблицы товаров:
- Game — игры (название, количество игроков, возрастной рейтинг);
- GameVariant — варианты издания игры (цена, скидка, статус наличия, описание);
- VariantImage — изображения вариантов товара;
- GameGenre — связь игр и жанров (многие-ко-многим).

Таблицы заказов:
- Cart — корзина пользователя;
- CartItem — позиции в корзине;
- Order — заказы;
- OrderItem — позиции заказа.

2.5 Проектирование программного интерфейса приложения

Взаимодействие между мобильным приложением и сервером осуществляется через REST API (Representational State Transfer Application Programming Interface). Все запросы, кроме авторизации и регистрации, требуют передачи токена JWT в заголовке Authorization [5].

Перечень конечных точек API представлен в таблице 3.

Таблица 3 — Конечные точки серверного API

| Метод | Адрес                        | Назначение                        |
|-------|------------------------------|-----------------------------------|
| POST  | /api/login                   | Авторизация, получение токена JWT |
| POST  | /api/users                   | Регистрация пользователя          |
| GET   | /api/game_variants           | Получение списка товаров          |
| GET   | /api/game_variants/{id}      | Получение информации о товаре     |
| GET   | /api/cart                    | Получение корзины пользователя    |
| POST  | /api/cart/items              | Добавление товара в корзину       |
| PUT   | /api/cart/items/{id}         | Изменение количества товара       |
| GET   | /api/me                      | Получение профиля пользователя    |
| GET   | /api/address_suggest         | Получение подсказок адреса        |
| GET   | /api/address_details         | Геокодирование адреса             |
| GET   | /api/address_reverse         | Обратное геокодирование координат |
| POST  | /api/orders/checkout         | Оформление заказа                 |

Формат обмена данными — JSON. Сервер возвращает соответствующие коды состояния HTTP: 200 при успешном выполнении, 401 при ошибке авторизации, 400 при некорректных данных запроса.

3 РЕАЛИЗАЦИЯ ПРИЛОЖЕНИЯ

3.1 Выбор средств разработки

Для реализации мобильного приложения выбраны следующие средства разработки:
- язык программирования Java — основной язык разработки под ОС Android [1];
- среда разработки Android Studio — официальная интегрированная среда разработки (Integrated Development Environment, IDE) для Android;
- система сборки Gradle — автоматизация сборки проекта и управление зависимостями;
- минимальная версия Android SDK (Software Development Kit) — 24 (Android 7.0);
- целевая версия Android SDK — 35 (Android 15).

Используемые библиотеки:
- Retrofit 2.9.0 — HTTP-клиент для взаимодействия с сервером [6];
- OkHttp — сетевой клиент, используемый Retrofit для выполнения запросов [7];
- Gson — преобразование объектов Java в JSON и обратно;
- Picasso 2.71828 — загрузка и кэширование изображений;
- Material Components — компоненты пользовательского интерфейса Material Design [8];
- ViewPager2 — компонент для реализации слайдера изображений;
- SwipeRefreshLayout — компонент для обновления данных жестом «потянуть вниз»;
- Google Play Services Location — определение местоположения устройства.

Для реализации серверной части использованы:
- язык программирования Python 3.11;
- фреймворк FastAPI — создание REST API [10];
- библиотека Peewee — объектно-реляционное отображение (Object-Relational Mapping, ORM) для работы с базой данных;
- СУБД SQLite — хранение данных.

3.2 Структура Android-проекта

Проект Android-приложения организован в соответствии со стандартной структурой, рекомендуемой для проектов Android Studio. Исходный код расположен в каталоге app/src/main/java/com/example/shop_exam/.

Основные классы приложения можно разделить на следующие группы:

Классы экранов (Activity):
- LoginActivity — экран авторизации пользователя;
- RegisterActivity — экран регистрации нового пользователя;
- MainActivity — главный экран с каталогом товаров;
- GameDetailActivity — экран детальной информации о товаре;
- CartActivity — экран корзины покупок;
- CheckoutActivity — экран оформления заказа;
- MapPickerActivity — экран выбора адреса на карте;

Классы адаптеров:
- GameAdapter — адаптер для отображения карточек товаров в сетке;
- CartAdapter — адаптер для отображения позиций корзины;
- ImageSliderAdapter — адаптер для слайдера изображений товара.

Классы сетевого взаимодействия:
- ApiClient — конфигурация HTTP-клиента и создание экземпляра Retrofit;
- ApiService — интерфейс с определением конечных точек API;

Классы моделей данных:

3.3 Реализация сетевого взаимодействия

Сетевое взаимодействие с сервером реализовано с использованием библиотеки Retrofit. Данная библиотека позволяет описывать конечные точки API в виде интерфейса Java с аннотациями, что упрощает поддержку и расширение кода [6].

Класс ApiClient отвечает за создание и настройку экземпляра Retrofit. В нём определён перехватчик (interceptor) OkHttp, который автоматически добавляет заголовок авторизации ко всем запросам.

Листинг 1 — Фрагмент класса ApiClient

```java
public class ApiClient {
    private static final String BASE_URL = "http://5.141.90.239:8003/";
    private static Retrofit retrofit = null;

    public static Retrofit getClient(Context context) {
        if (retrofit == null) {
            OkHttpClient.Builder httpClient = new OkHttpClient.Builder();
            httpClient.addInterceptor(chain -> {
                Request original = chain.request();
                String token = TokenStore.getToken(context);
                Request.Builder builder = original.newBuilder();
                if (token != null && !token.isEmpty()) {
                    builder.header("Authorization", "Bearer " + token);
                }
                return chain.proceed(builder.build());
            });
            retrofit = new Retrofit.Builder()
                    .baseUrl(BASE_URL)
                    .addConverterFactory(GsonConverterFactory.create())
                    .client(httpClient.build())
                    .build();
        }
        return retrofit;
    }
}
```

Интерфейс ApiService определяет все конечные точки API с указанием HTTP-метода, пути и параметров запроса. Аннотации Retrofit (@GET, @POST, @PUT, @Body, @Query, @Path) позволяют декларативно описать структуру запроса.

3.8 Перспективы развития приложения

Разработанное приложение реализует базовый функционал интернет-магазина. Для повышения удобства использования и расширения возможностей приложения целесообразно реализовать ряд дополнительных функций.

Профиль пользователя

В текущей версии приложения отсутствует отдельный экран профиля пользователя. Данные профиля (имя, телефон) используются только при оформлении заказа и загружаются из серверного API. Реализация полноценного экрана профиля позволит пользователю:
- просматривать и редактировать личные данные (имя, фамилия, телефон, электронная почта);
- просматривать историю заказов с возможностью повторного заказа;
- управлять сохранёнными адресами доставки;
- изменять пароль;
- выходить из учётной записи.

Для реализации экрана профиля потребуется создать новую Activity (ProfileActivity) и добавить соответствующие конечные точки на сервере для обновления данных пользователя и получения истории заказов.

Поиск товаров

Поиск товаров является важной функцией для приложений с большим каталогом. Реализация поиска включает следующие компоненты:
- поле ввода поискового запроса в верхней части экрана каталога;
- отправка запроса на сервер с параметром поиска;
- фильтрация результатов по названию игры, описанию и другим атрибутам;
- подсветка найденных совпадений в результатах.

На стороне сервера поиск может быть реализован с использованием оператора LIKE в SQL-запросах для простых случаев или с применением полнотекстового поиска SQLite FTS (Full-Text Search) для более сложных сценариев.

Листинг 11 — Пример реализации поиска на сервере

Фильтры каталога

Фильтрация товаров позволяет пользователю быстро найти товары по заданным критериям. Для приложения магазина настольных игр актуальны следующие фильтры:
- по количеству игроков (например, «для 2 игроков», «для компании 4+»);
- по возрастному рейтингу (0+, 6+, 12+, 18+);
- по жанру (стратегия, кооперативная, карточная);
- по наличию («только в наличии»);
- по цене (диапазон от и до);
- по наличию скидки.

ЗАКЛЮЧЕНИЕ

В ходе выполнения курсового проекта разработано мобильное приложение интернет-магазина настольных игр для операционной системы Android. Приложение реализует полный цикл покупки: от авторизации и просмотра каталога до оформления заказа с выбором адреса доставки.

В процессе работы решены следующие задачи:
- проведён анализ предметной области и существующих решений в сфере мобильной электронной коммерции;
- сформулированы функциональные требования к приложению на основе пользовательских сценариев;
- спроектирована клиент-серверная архитектура системы с использованием REST API;
- спроектирован пользовательский интерфейс в соответствии с рекомендациями Material Design;
- реализовано мобильное приложение на языке Java с использованием библиотек Retrofit, OkHttp, Picasso и компонентов Material Components;
- реализована интеграция с картографическим сервисом 2ГИС для адресных подсказок и выбора точки на карте;
- реализована серверная часть на базе фреймворка FastAPI с панелью администратора;
- проведено функциональное тестирование приложения.

Разработанное приложение демонстрирует практическое применение современных подходов к разработке мобильных приложений: асинхронное сетевое взаимодействие, декларативное описание API, паттерны пользовательского взаимодействия (смахивание для удаления, потянуть для обновления), интеграция с внешними сервисами через WebView и JavaScript-интерфейс.

Возможные направления дальнейшего развития проекта подробно рассмотрены в разделе 3.8. Помимо профиля пользователя, поиска и фильтров, перспективными являются:
- реализация push-уведомлений о статусе заказа с использованием Firebase Cloud Messaging;
- добавление функции «Избранное» для сохранения понравившихся товаров;
- поддержка офлайн-режима с локальным кэшированием данных в SQLite;
- интеграция с платёжными системами для онлайн-оплаты заказов;
- локализация приложения на другие языки.
